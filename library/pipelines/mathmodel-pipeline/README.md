# 数模管线 V5.2 —— 参谋组 + 单一拍板者 + 产物回归门

> 四模型参谋只交候选与分歧 → **单一拍板者定稿（定稿即法律）** → 求解进 registry →
> 数值门禁 → 装配写作 → 四评 → 修复回路 → **产物分数回归门**

## 这份管线解决什么

把一道数学建模竞赛题，变成**一篇过得了分数门的论文**。

它针对的是 v5.1 暴露出来的三个致命伤：

| v5.1 的病 | 症状 | v5.2 的药 |
|---|---|---|
| **验收测错对象** | 验收测「评审能不能找到错」，不测「产物烂不烂」 | **S7 产物分数回归门**：分数不过基线，产物不出管线 |
| **责任稀释** | 四建模手商议 → 无人对方案负责；951 违规三层人看见、零层人修复 | **S1.5 单一拍板者**：一个人拍板，定稿即法律 |
| **写作无全局责任** | writer 照抄注册表 → 新旧值拼贴（−843.92/−675.54）、章节错乱、文献幻觉 | **S4 改成装配**：模板+定稿+注册表，writer 只做语言组织 |

## 九个阶段

```
S0   读题解析（确定性 + LLM）      要求单元 / 硬约束全集 / 附件口径 / 题型判定
S1   参谋组（四模型，隔离实例）     只交候选方案，不产定稿；产出：四份方案 + 分歧清单
S1.5 总设计定稿（单一拍板者）★      自动=新开 DeepSeek 零上下文 / 半自动=博士拍板
S2   求解                        按定稿逐问写求解器，数字全进 registry，SHA 防漂移
S3   数值门禁（确定性代码）        重跑 SHA 全等 + 预测量级一致性 + 基准并置
S4   装配写作（重构）             模板 + 定稿 + 注册表 → 装配；writer 只做语言组织
S5   四评 v2.8                    GLM / Kimi / 新开 DS 全权 + Qwen 影子校准阶梯
S6   自动修复回路                 修订单 → 易修复就地 repair，需重算回灌 S2 → 再评审
S7   产物分数回归门（最终出口）    评审分 ≥ 上一版基线，否则产物不出管线
```

## 六条铁律

1. **定稿即法律** —— S1.5 定稿是唯一真源，后续阶段不得自创方法/参数/口径
2. **单一责任人** —— 每问求解、每个数字、每段正文都有且仅有一个责任人
3. **数字唯一入口** —— 论文数字只从 registry 注入；writer 禁止生成数字/文献/声明
4. **修一处 → 下游全链重做**（freshness 已实现）
5. **产物分数进门禁** —— 不过 S7 不出管线
6. **零上下文隔离** —— 参谋、拍板、四评、写作各实例互不带上下文

## 为什么 S1.5 必须「新开实例」

撰写/参谋实例的上下文里带着**自己的方案偏好**，换题后容易路径固执。
新开实例只带本场材料（四份方案 + 分歧清单 + 硬约束），总结与挑选更中立。

定稿产出后 **hash 登记**，任何下游产物引用定稿版本号；定稿被改 → freshness 判定下游全链作废。

## 怎么跑

```bash
# 本体仓库
git clone https://github.com/xtr0928/Multi-agent-mathematical-modeling
cd Multi-agent-mathematical-modeling

# 规划段（Stage A：需求澄清 → 搜类似题 → 选型 → 设计文档）
python pipeline/planning.py

# 执行段（Stage B：四模型分工求解）
python pipeline/orchestrator.py
```

需要四个模型端点同时可用：**GLM / Kimi / DeepSeek / Qwen**。
