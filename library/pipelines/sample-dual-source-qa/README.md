# 双源问答 + 事实核对

> 拿「问题 + 参考文档」起草回答，再独立核对事实后定稿 —— 展示汇合语义与注释注入

## 这份管线解决什么

输入一个问题和一份参考文档，输出**一版带出处、且经过独立核对**的回答。

它是**用来看格式细节的**，两个节点各演示一个关键语义：

| 位置 | 演示什么 |
|---|---|
| `起草回答.material` | **`mode: all`** —— 这个端口同时收「问题」和「文档」两份，缺一份就没法起草 |
| `定稿.fact_check` | **`required: false`** —— 核对清单是增强项，没它也照常出稿 |
| `定稿.bottom_line` | **注入型注释** —— `定稿底线` 这条注释注入到 system 提示词 |
| `事实核对` 上的便签 | **挂靠型注释** —— 只贴在画布上给人看，不注入 |

## 怎么跑

流谱生成器打开 `pipeline.flow.json`；提示词是占位符，要自己填才能跑。

## 前置条件

- 一个 LLM 端点即可（示例里用了 DeepSeek + GLM 两个，可以都改成同一个）

## 注意事项

- **`事实核对` 刻意不吃初稿** —— 只拿原始文档去查。若是让它读初稿，它会顺着初稿措辞找依据，等于让写的人自己批改。它上面挂的注释解释了这点。
- **`起草回答` 的 `mode: all` 不能省** —— 单来源时 `mode` 是噪音（三个取值等价），但这里有两个来源，不写就无法确定「一份到齐就动手」还是「两份都要」。
- 提示词是省略号，属于示例占位。
