# 测试说明

本目录包含项目的浏览器端测试。所有用例通过 `test.html` 在浏览器中加载执行，不依赖任何测试框架，测试页只读取全局对象 `window.XTR`，通过它调用被测函数并比对期望结果。

## 目录结构

```
tests/
├── test.html                  # 测试页（唯一入口）
├── README.md                  # 本文件
└── cases/
    ├── graph.cases.json       # 连线规则用例（canConnect）
    ├── validate.cases.json    # Schema 校验用例（pipeline / layout）
    └── compat.cases.json      # 版本兼容判定用例（$version 档位）
```

## 如何运行

有以下三种运行方式，任选其一：

### 方式一：双击直接打开

直接双击 `tests/test.html`，浏览器会在本地打开测试页并自动执行所有用例。

注意：此方式受浏览器 `file://` 同源策略限制（见「已知限制」），个别需要 `fetch` 的场景可能失败。若遇到用例莫名失败，请改用方式二确认。

### 方式二：本地静态服务器（推荐）

在仓库根目录启动一个静态服务器：

```bash
python -m http.server 8000
```

然后在浏览器访问：

```
http://localhost:8000/tests/test.html
```

这是开发过程中最常用的方式，能规避 `file://` 同源策略问题，用例结果最可靠。

### 方式三：部署到静态站点

将整个仓库部署到任意静态托管服务（GitHub Pages、内网静态服务器等）后，访问部署地址下的 `/tests/test.html` 即可。这适合在无法本地起服务的环境中复现和确认测试结果。

## 测试机制

测试页只读 `window.XTR`，不依赖任何测试框架（无 Jest / Mocha / Vitest 等）。`test.html` 会：

1. 加载被测代码，使其在全局暴露 `window.XTR`；
2. `fetch` 读取 `cases/` 下的三个 JSON 用例文件；
3. 对每个用例调用 `window.XTR` 上的对应方法，将实际结果与用例中的 `expect` 字段比对；
4. 在页面上逐条渲染通过 / 失败结果。

断言均为简单的值比较或包含性检查（如 `reasonContains`、`path` + `keyword` 精确匹配、`expectStatus` 相等），任何一条不匹配即记为失败。

## 如何新增用例

按以下三步操作：

1. **改 case JSON**：在 `cases/` 下对应的用例文件中新增条目（如 `graph.cases.json` 的 `canConnect` 数组、`validate.cases.json` 的 `groups` 数组、`compat.cases.json` 的 `cases` 数组），写清楚 `desc`、输入和 `expect`；
2. **在 `test.html` 加断言组**：如果是全新的能力（而非既有能力的又一组输入），在 `test.html` 中补充一个断言组，说明如何调用 `window.XTR` 上的对应方法、如何比对结果；
3. **跑一次全绿**：用上述任一运行方式跑一次测试，确认所有用例（含新增用例）全部通过后再提交。

## 用例只增不减

自 M2 之后，`cases/` 下的用例只增不减：已合入的用例不得删除或削弱断言，只允许在发现用例本身写错（与规格不符）时修正，修正须在提交说明中写明原因。这保证了测试结果在时间维度上可对比、回归始终有迹可循。

## 结果如何解读

- 页面按用例分组渲染，每条用例单独标注 **通过（绿）** 或 **失败（红）**；
- 失败的用例会同时展示用例描述、期望结果和实际结果，可直接定位差异；
- 页面顶部有汇总（总数 / 通过数 / 失败数），失败数为 0 即视为「全绿」；
- 若整组用例全部报错且提示加载失败，通常是运行方式的问题（如 `file://` 下 `fetch` 被同源策略拦截），请先换用 `python -m http.server` 重跑再判断。

## 已知限制

- **`file://` 同源策略**：直接双击打开 `test.html` 时，部分浏览器会因同源策略拦截对 `cases/*.json` 的 `fetch`，导致用例无法加载。这是浏览器安全策略所致，非代码缺陷，请改用静态服务器方式运行。
- **Node 环境不可跑**：测试页强依赖浏览器环境与 `window` 全局对象，不能在 Node.js 中直接执行（如 `node test.html` 或用 Node 脚本驱动），也没有对应的 Node 测试脚本。如需在 CI 中跑测试，请使用无头浏览器加载该页面。
